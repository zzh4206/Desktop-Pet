# 桌宠 分发打包策略（mac 端）

> 立项 2026-10-04。目标：给外部测试者一个「双击安装、跑得起来、抠不出源码」的 mac 分发包。
> 当前状态：**仅策略，未执行**——代码仍在调试期，本文档只固化决策与执行清单，触发条件满足前不动代码。

---

## 一、已定决策

- **D1 范围**：我方只负责 **mac 端**安装包；win 端打包由 win 端另行决定（但 §三的共享层路径改造对两端都有益，`hotkey_win.py:290` 引用 `app.py` 文件是 win 端的雷，已在此预告）。
- **D2 打包器 = Nuitka（开源免费版）**：编译为机器码的核心能力在免费版；Commercial 的反编译加固（常量混淆等）才收费，QA 分发用不上，**不花钱**。放弃 PyInstaller 的原因：字节码（.pyc）可被 pyinstxtractor + pycdc 还原成近似源码，保护不足。
- **D3 产物形态**：Nuitka `--mode=app` → `.app` bundle → **DMG**（`hdiutil`/create-dmg，拖入 Applications 布局）。不用 onefile：包体 400MB+，每次启动解压临时目录、首启慢。
- **D4 Gatekeeper**：现阶段**不买** Apple Developer 账号（$99/年）。无签名无公证 → 测试者首启报「已损坏」，须知放一行 `xattr -cr /path/to/桌宠.app` 解决。对外正式发布时再升级（见 §五）。
- **D5 LLM key**：零配置可跑已就绪（`app.py:584` 无 key → 宠物照跑、聊天禁用、气泡提示 + 首启引导）。**严禁**把自己的 key 编进包里。
- **D6 分发渠道（首轮）**：网盘/直传 zip 或 DMG（蓝奏云单文件 100MB 限超了；微信/阿里云盘/百度盘可）。私有仓库的 Release 附件匿名不可下载，GitHub 渠道不通。

## 二、保护边界（诚实声明）

Nuitka 保护的是**逻辑代码**（行为 FSM / LLM 工具链 / proactive 等编成机器码）。以下**保护不了**，接受即接受：

- 美术资源：`assets/` 序列帧原样在包内可提取（本来就是给人看的）；
- QML（`pet/ui/*.qml`）明文（QML 预编译可行性未调研，暂不做）；
- config 结构与默认值。

双保险：仓库私有 + 不给测试者 repo 权限，安装包保护只防「从分发产物抠代码」。

## 三、代码适配清单（打包前置，共 5+1 处）

现状：资源路径全部 `__file__` 相对拼接，打包后模块在 bundle 内 `_internal` 类似目录，全部失效。

1. 新增资源根助手（建议 `pet/paths.py` 或并入 `platform.py`）：`resource_root()` —— frozen 模式返回 bundle 资源根，dev 模式回退 repo 根。**此改动 dev 模式行为零变化**，理论上调试期也可先行合入（另议）。
2. 替换 5 处拼接：
   - `app.py:180`（pet/models onnx 模型根）
   - `app.py:479`（assets/rig）
   - `app.py:699`（pet/ui/main.qml）
   - `app.py:1499`（assets/rig_*_walk_v1）
   - `pet/asset_provider.py:210`、`pet/config.py:25`（config.example.json）
3. win 端预告：`pet/hotkey_win.py:290` 引用 `app.py` 文件路径，打包后不存在，须改 `sys.executable`（共享层助手可一并提供）。

## 四、执行清单（触发后按序）

**触发条件**：v0.19.x 功能收敛、进入「发外部测试」节点时启动（预计半天调通首次构建 + 半天验证）。

1. **构建脚本** `tools/build_mac.sh`：
   - `nuitka --mode=app --enable-plugin=pyside6`；数据文件显式包含：`assets/`、`pet/ui/*.qml`、`pet/models/`、`config.example.json`；
   - 剔 `assets/reference/`（6.7MB 对位建模参考图，运行时不用）；
   - 留意 tokenizers / onnxruntime 的 hidden imports 与自带数据文件；
   - 首次构建慢（C 编译，clang/Xcode CLT 本机已有），迭代有缓存。
2. **DMG**：`hdiutil` 或 create-dmg 出拖拽安装布局，命名带版本号（如 `DesktopPet-0.19.x-mac.dmg`）。
3. **《测试者须知》随包**（一页）：
   - `xattr -cr` 解 Gatekeeper；
   - macOS 权限预告（辅助功能等，开发机已授过的首启都会重弹）；
   - 无 key 行为说明（想试聊天→首启引导各自填 DeepSeek key）；
   - 日志位置（出问题回传日志）+ 版本号自查（日志首行 `APP_VERSION`）。
4. **验证 checklist**（干净管理员账号/另一台 mac）：
   - DMG → 拖入 Applications → 首启全流程（含权限弹窗顺序）；
   - 无 key 路径：宠物可跑、聊天禁用气泡出现；
   - 单实例锁：二次启动静默退出；
   - 冷启动耗时可接受；`assets` 加载无缺图。

## 五、后续演进（现阶段均不做）

- **GitHub Actions 出包**：若 win 端需要统一 CI 或多轮迭代分发（届时可开 public release 仓库）；
- **Apple Developer 签名 + 公证**：对外正式发布、面向不熟的人时；
- **托盘「导出诊断包」**：logs + 脱敏 config + 版本一键打包，方便测试者回传；
- **QML 预编译**：若 QML 明文暴露成为实际顾虑再调研。

## 六、开放问题

- **资源瘦身**：全量 384MB vs 锁成长阶段砍到 ~200MB（`rig_final_walk_v1` 86M / `frames` 77M / `rig_adult_walk_v1` 73M 为大头）——影响传输渠道与首启速度，执行前必须拍板；
- 资源根助手（§三.1）是否提前在调试期合入（行为零变化，可当普通重构测试），还是与打包一起做。
