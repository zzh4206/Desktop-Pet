# 主动纠缠互动：版本规划报告（v0.24 线）

> 立项：2026-10-08。四模块独立版本线之一（0.23 天气 / 0.24 纠缠 / 0.25 番茄 / 0.26 语音），
> 用户指定实现顺序第 2 位（2026-10-08 用户拍板与番茄对调：纠缠 0.24、番茄 0.25）。设计初稿见 wiki [设计-主动纠缠互动](../../wiki/主动纠缠互动.md)（实际文件名：设计-主动纠缠互动.md）。

## 1. 目标与范围

**一句话**：桌宠具备「被关注的需求」——长时间没被理睬会主动凑过来求摸头、挡光标打滚、气泡撒娇；用户被烦到但被治愈。

**定位区分**（立项时已与现有能力划界）：v0.6 主动关怀=功能性提醒；v0.19.2 需求表达=数值触线被动触发；**本线=无功利目的的性格化求关注**。

**本线做**：attention 陪伴度数值 + 纠缠行为池首批 2 个（奔向光标求摸头 + 气泡撒娇）+ 全套护栏。
**本线不做**（后置登记）：叼物/边缘探头等立绘依赖行为、attention→NEGLECTED 分支耦合调参、天气联动纠缠（「下雨天更黏人」，依赖 0.23 的 Sensors 接线）。

## 4. 风险与依赖

- **独立性**：不依赖 0.23/0.26；对 0.25 番茄是**单向软依赖**——本线（0.24）先于番茄实现，FOCUS 静默检查以「focus 模块存在且处于 FOCUS」的防御性探测书写，缺模块视为非专注不崩；0.25 番茄落地 FocusSession 后自动接通。
- 最大风险是体验而非技术：烦人度调参需要实机浸泡观察（建议上线后 1–2 周用户反馈迭代，护栏默认从严：2 次/时起步）。
- 立绘产能：首批两行为零新资产（复用现有移动 + 趴下/待摸头姿态需确认现有帧或 rig 姿态可覆盖）。
