# 天气感知与提醒：版本规划报告（v0.23 线）

> 立项：2026-10-08。四模块独立版本线之一（0.23 天气 / 0.24 纠缠 / 0.25 番茄 / 0.26 语音，2026-10-08 对调原 24/25 段），
> 用户指定实现顺序第 1 位。设计初稿见 wiki [设计-天气感知与提醒](../../wiki/设计-天气感知与提醒.md)。
> 版本线：**0.23.0 起递增，每次 commit patch +1**；版本单一源 `pet/__init__.py.__version__`，每次提版同步 README 版本沿革。
> 用户说「提交」= 只提交与 0.23 相关的改动（对齐 0.19 线纪律）。

---

## 1. 目标与范围

**一句话**：给桌宠接入天气环境感知，服务于主动提醒、聊天问答、行为调制三个消费方。

**本线做**：数据源 + 快照缓存 + 主动提醒 + LLM 工具。
**本线不做**（后置登记，不承诺）：AQI、IP 自动定位默认化、行为调制（§4 模块5，可选拆后）、打伞动画等立绘资产项。

## 2. 现状基线（代码锚点）

| 事实 | 锚点 |
|---|---|
| 提醒链与当日去重持久化模式 | `pet/proactive.py`（greeted/festivaled + proactive_state.json 原子写） |
| 工具注册与危险分级 | `pet/tools_schema.py` ToolRegistry（get_weather 归无危险级） |
| DND / 深夜 / 全屏检测 | proactive + 吃鼠标既有检测链 |
| 配置 schema | `pet/config.py`（config v2 风格，参照 v0.19.1 迁移） |
| 网络红线 | 请求间隔 >5s（30–60 min 缓存远松于此） |

## 3. 提交阶梯（0.23.0 → 0.23.n）

| 版本 | 模块 | 内容 | 验收 |
|---|---|---|---|
| 0.23.0 | 核心 | `pet/weather.py`：WeatherProvider（Open-Meteo）→ WeatherSnapshot + 30min 缓存 + 离线用最后快照并标过期；纯函数层单测（HTTP mock） | 断网不崩、缓存过期标注正确 |
| 0.23.1 | 配置 | config 增 `weather.city/refresh_min/alerts.*`（阈值：降水概率、较昨日温差）；config.example.json 同步 | schema 校验 + 旧 config 迁移 |
| 0.23.2 | 主动提醒 | 挂 ProactiveScheduler：今日首次刷新触发「带伞/降温/高温」气泡；每类每日一次落 proactive_state 去重；DND/深夜静默 | 当日不重复、DND 不出声出泡 |
| 0.23.3 | LLM 工具 | ToolRegistry 注册 `get_weather`（读缓存快照，不即时拉网）；聊天可问穿什么/下雨吗 | 工具返回 JSON 快照 + 单测 |
| 0.23.4 | 收尾 | README 配置节 + 版本沿革 + 本地数据说明补 weather_cache.json 可删 | README 校对 |

> 模块 5（可选）：WeatherSnapshot 进 `Sensors` 供行为调制（雨天 WANDER 降频）——若本线周期紧张可顺延至 0.24 纠缠线一并接线（纠缠行为可消费天气）。

## 4. 风险与依赖

- **独立性**：不依赖其他三线；唯一交点是模块 5 的 Sensors 接线（可拆）。
- 数据精度：Open-Meteo 对国内城市先试用；精度不足的和风天气作 `weather.provider` 备选位预留，不在本线实现。
- 提醒措辞遵循诚实护栏：用「看起来要下雨」，不做保证性声明。
