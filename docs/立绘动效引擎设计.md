## 一、定位与目标

在「路线 C 分层绑骨展示层」之上，抽出一个**独立运动引擎**：纯 Python 逻辑（`motion.py`），**零 Qt / QML import**。当前 `rig_scene.qml` 里内嵌的呼吸/行走律动/速度倾斜/落地压扁/部件正弦摆动，全部下沉到这个 Python 模块里由引擎计算；QML 退化成**哑渲染器**——每帧只接收引擎产出的一份姿态数据（角度/缩放/位置），照着把图摆上去，不再有任何运动决策。

### 1.1 核心诉求（四条铁则）

| # | 诉求 | 含义 |
|---|---|---|
| ① | 可单元测试 | 不 import Qt/QML ⇒ pytest 直接喂输入、断言输出，无需起 QApplication 或 offscreen 场景 |
| ② | 确定性 | 同输入同输出：所有积分/正弦/随机都用固定种子或解析函数，回放姿态逐帧一致 |
| ③ | 三阶段共用同一动作规范 | YOUNG / ADULT / FINAL 三阶段只有资产不同，动作参数与格式同一份，随阶段演化不受阻 |
| ④ | 后端中立 | 引擎只产数据、不碰渲染；未来可直接驱动 `Renderer3D`（`设计思路.md` §二 `Renderer` 协议预留位） |

### 1.2 数据流（单帧）

```
FSM 实况(speed/mode/airborne) ──┐
清单参数(manifest 可选新字段) ──┼──▶ motion.py 每帧 step(dt) ──▶ 部件姿态集 {angle, scale, pos, shadow}
事件(落地/点击/朝向) ──────────┘                              │
                                                            ▼
                                     QML 哑渲染器：只照着姿态摆图，不做决策
```

> 一句话边界：**运动是数据，渲染是显示**。引擎不 import Qt，QML 不含运动逻辑。

## 二、新 vs 原差异

### 2.1 对照表

| 维度 | 原（paper-doll-lite，`rig_scene.qml`） | 新（独立运动引擎 `motion.py`） |
|---|---|---|
| 运动逻辑位置 | 内嵌 QML，单一时钟 + 纯绑定合成 | 独立 Python 引擎，QML 退化成哑渲染器 |
| 部件摆动 | 固定正弦 `amp·sin(2πt/period)` | 二阶**弹簧-阻尼物理**，替代固定正弦 |
| 部件关系 | 平铺 `parts[]` 列表，无层级 | **父子层级**（新增 `parent` 字段）+ follow-through |
| 身体运动 | 呼吸均匀缩放 + 速度倾斜 + 落地压扁 + 走路颠簸，各自独立 | **运动栈分层**：L0 常驻 / L1 反应 / L2 弹道，三层求和互不覆盖 |
| 新增能力 | 无 | **视线**（瞳孔 + 头随视线 + 扫视）、**接触阴影** |

### 2.2 一句话总结

> 原来是在渲染层里加正弦变换让图动；新是把「运动」当成一份**可测试、可复用、分层的数据规范**，渲染层只负责照着摆图。

## 三、引擎三大积木（按依赖顺序）

依赖顺序：**① 弹簧 → ② 骨架 → ③ 运动栈**。骨架建立在弹簧之上（每个关节都是一根弹簧），运动栈把各动作源组织成互不覆盖的层，最终叠加到骨架上。

### 3.1 积木① 弹簧（spring）

每部件维护 `(angle, angVel)` 状态，用**二阶弹簧-阻尼积分器**替代固定正弦。目标角 `g`、目标角速度 `q`（通常 `q=0`）：

```
s = (2πf)²            # stiffness：f = 期望自振频率(Hz)
d = 4·ln2 / halflife  # damping：halflife = 包络衰减一半的时间(s)
```

离散积分用 **semi-implicit Euler**（先速度后位置，辛积分器，稳定保能量）：

```python
def spring_step(x, v, g, s, d, dt, q=0.0):
    v += dt * s * (g - x) + dt * d * (q - v)   # ① 先更新速度
    x += dt * v                                # ② 再用新速度更新位置
    return x, v
```

阻尼比 `ζ = d / (2√s)`：取 **ζ ≈ 0.5–0.8 欠阻尼**——过冲回弹正是「软感」的来源（临界阻尼无回弹、过阻尼偏笨）。突发冲量不改目标角，直接 `v += J`，随后弹簧自然振荡衰减。

### 3.2 积木② 骨架（skeleton）

在弹簧之上，把 pivot 部件组织成**父子链**：

- **新增 `parent` 字段**：部件不再平铺，pivot 部件父子成链；子部件的目标角 = 父部件本帧已更新后的角度，逐层用弹簧跟随 ⇒ 天然产生 follow-through + 回弹，无需手工调时间轴。

```python
# parts[0] 是根（由运动栈驱动），其余是子级链
for p in parts[1:]:
    p.target = p.parent.angle          # 子级目标是父级本帧已更新后的角度
    p.angle, p.vel = spring_step(p.angle, p.vel, p.target, p.s, p.d, dt)
```

- **CPU 铰链链**（软弯曲）：长部件（头发/尾巴/裙摆）切成 N 段子精灵，每段按衰减权重旋转，做**沿长轴的加权旋转**：

```
θ(u) = θ_max · w(u)
w(u) = u²        # u∈[0,1]，u=0 在 pivot、u=1 在尖端；根硬尖软
```

- **不用 ShaderEffect**：`software` 后端完全不渲染 ShaderEffect，且 Qt6 要求 `.qsb` 离线编译管线（Vulkan 风格 GLSL → SPIR-V → HLSL/MSL），与「全后端兼容 + 确定性 + 可脚本化」冲突。CPU 铰链链零新像素、全后端安全。

### 3.3 积木③ 运动栈（motion stack）

把各动作源组织成三层，**同帧三层求和、互不覆盖**（替代原来「呼吸/倾斜/压扁/颠簸各自独立写属性」的散点式）：

| 层 | 内容 | 语义 |
|---|---|---|
| **L0 常驻** | 分层呼吸 / 眨眼 / 视线 / 摆件 | 永不停止的底噪，决定「活」的基本盘 |
| **L1 反应** | 速度倾斜 / 落地 squash / 视线 | 对 FSM 实况的即时反馈（速度、落地沿） |
| **L2 弹道** | 走路 / 掉落 / 抛掷 | 一次性/持续性的大位移动作，压在 L0/L1 之上 |

> 注：视线跨 L0 与 L1 两层——L0 是**随机扫视**（saccade，常驻底噪），L1 是**跟随目标**（LookAt，对鼠标的反应）。两者同属「视线」但来源不同。

## 四、落地默认参数表

> 全部进 `motion.py` 默认常量 + manifest 可选覆盖；来源标注：**〔Live2D 官方〕〔FF7 CEDEC〕〔Celeste/HollowKnight/DeadCells 实测〕〔Daniel Holden + Spine〕〔Shimeji/Oneko 源码〕〔经验值〕**。

### 4.1 呼吸（来源：Live2D 官方）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 呼吸纵向浮动 | 周期 **3.2s**；幅度 **±1–2% 身高**（实机落地 ±2.5px，v0.15.1 由 ±2px→3px→2.5px 校准） | 全体件整体 y 平移（周期官方、幅度经验） |
| 头点头（AngleY） | **±4° @ 3.5s** | |
| 头歪头（AngleZ） | **±5° @ 5.5s** | |
| 头左右转（AngleX） | **±7.5° @ 6.5s** | |
| 身体左右漂（BodyAngleX） | **±2° @ 15.5s** | 超低频漂移 |

分层多周期要点：**头部高频微动 + 身体超低频漂移**叠加；头三轴周期 3.5 / 5.5 / 6.5s **互不为整数倍**，避免规律感（去掉「整身同频摆动」的机械感）。

### 4.2 眨眼（来源：FF7 CEDEC + Live2D 官方）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 间隔 | 随机 **3–6s**（机制上限 **0–12s**） | Live2D 官方机制 = 0~2×均值随机 |
| 开合总时长 | **0.1–0.4s** | |
| 曲线 | **快闭慢开**，`scaleY 1→0.05→1` | 闭眼时间 < 睁眼时间 |
| 同步 | 左右眼**同步** | |
| 半闭 | 支持**半闭**（scaleY 停在中间值） | 更自然 |

### 4.3 视线（来源：Live2D LookAt + FF7 CEDEC）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 瞳孔偏移 | **±0.15–0.25 眼宽** | 避免「瞪出眼眶」 |
| 头随视线 | **±2–5°** | 远小于瞳孔，眼先动、头慢跟 |
| 扫视（saccade） | 每 **2–6s** 一次 | 常驻底噪，盯死会显「死」 |

### 4.4 摆动（来源：Daniel Holden + Spine）

弹簧参数（f / halflife → s / d 换算见 §3.1）：

| 部件 | f (Hz) | halflife (s) | 感觉 |
|---|---|---|---|
| 头发 | **2.0** | **0.10** | 快速响应 |
| 裙摆 | **1.0** | **0.20** | 柔软飘动 |
| 呼吸 | **0.5** | **0.40** | 很轻慢摆 |

通用规则：

| 规则 | 默认值 |
|---|---|
| 相位滞后 | **20–40°**（≈ **60–120ms**） |
| 摆件幅度 | 主体幅度的 **1.5–2×** |
| 根→梢 | **逐段延迟 + 幅度递增** |

### 4.5 重量（来源：Celeste / Hollow Knight / Dead Cells 实测）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 落地 scaleY | **0.82–0.9** | 可爱 0.8 / 写实 0.85 |
| scaleX | **1 / scaleY** | 体积守恒（宽高反比，否则像「缩水」） |
| 回弹 overshoot | **1.05–1.15×** | |
| 时长 | **0.05–0.15s** | 60fps 下 3–9 帧 |
| pivot | **脚底** | 保证 squash 向下压、非中心缩放 |
| 接触阴影 | **lerp(0.6→1.0)** | 随距地高度反比缩放 |

### 4.6 走路 / 追逐（来源：Shimeji / Oneko 源码）

| 参数 | 默认值 | 说明 |
|---|---|---|
| 速度 | **~100px/s** | Shimeji ≈100px/s、Oneko ≈128px/s |
| 前倾 | **2–4°** | 沿前进方向 |
| 颠簸 | **2–3Hz** | |

## 五、剪枝结论

### 5.1 保留（6）

1. 弹簧物理
2. 骨骼层级 + follow-through
3. 分层呼吸
4. 眨眼 + 视线
5. 落地 squash + 接触阴影
6. CPU 铰链链

### 5.2 砍（3）

| 被砍项 | 替代 / 理由 |
|---|---|
| ShaderEffect 软弯曲 | 用 CPU 铰链链（§3.2）；software 后端完全不渲染 + Qt6 `.qsb` 管线 |
| 粒子 / 光影 | 收益比最低，去掉 |
| Perlin 风噪声 | 改用**非谐波多正弦**确定性替代（`Σ Aᵢ·sin(2πfᵢt+φᵢ)`，fᵢ 取非谐波比避免周期锁死） |

### 5.3 挂起（2）

1. 抓边 / 爬窗（需窗口几何 + 抓边姿态，成本最高，留后）
2. 大型随机 idle 动作集（先做 **3–5 个固定微动作**，不做概率大集合）

## 六、兼容与降级铁律

延续 `设计思路.md` 既有的「展示层永不阻断启动」降级铁律，对运动引擎再加三条：

| # | 铁律 | 说明 |
|---|---|---|
| ① | 新 manifest 字段**全部可选** | 缺省 = 现状行为（旧清单全兼容，同 `kind` 字段「缺省 sway 向后兼容」的既有做法） |
| ② | `motion.py` import 失败 / 字段非法 | → 回退现有**静态正弦**（`rig_scene.qml` 现有 sway/limb/blink 路径） |
| ③ | 展示层永不阻断启动 | 引擎降级 = 画面退化，不是崩溃；装配侧只看返回值 |

> 铁律精神：引擎是**增强**，不是**前置条件**。任何一环（import / 清单 / 场景）不满足，都收敛回 v0.13/v0.14 已验证的现状行为。

**叠加通道（超出本文档原范围，已一并落地）**：

- **v0.16 风通道**（`pet/wind.py`）：Open-Meteo 实时风力 → L0 sway 幅度倍率（Beaufort）+ 顺风偏置（`wind_direction_to_bias`），无网/无城市回退静态。

### 7.2 回退·独立·待合并（v0.0.3）

**命名约定**（v0.15.1 起）：**原有引擎** = frames 帧动画后端（成熟、防御性编程成熟）；**新引擎** = 正在开发的 motion / wind / sun / rig。

实机审查结论：新引擎整体未达预期，且 P1「等价迁移」把原引擎的老毛病（走路 2 帧踏步 / 呼吸过轻）也 1:1 照搬了过来。故**先与原有引擎独立开来**，避免把未成熟引擎继续压在 app 主链路上；后续合回必须走**接口接入**：

```
原有引擎(frames) ← 中间层 EngineBridge ← 新引擎的有效部分(motion/wind/sun)
```

| 动作 | 落地 |
|---|---|
| **app 回退** | `app.py` 锁定 `presentation="frames"` 原有引擎接管；风/光影/rig 接线全部注释，标记 `⚠️ 回退·待合并` |
| **中间层** | `pet/engine_bridge.py`：`Enrichment`（输出契约）+ `Enricher`（接口 ABC）+ `NullEnricher`（原有引擎缺省恒等）+ `MotionEnricher`/`ChannelEnricher`（新引擎有效部分）+ `EngineBridge`（防御性门面，任一环抛错永久降级恒等） |
| **有效部分** | 只纳入已过回归锁的部分：motion 32 · wind 18 · sun 27；paperdoll 部件步态 / 2 帧走路**不**纳入 |
